2. Novo emissor v2

Problema comprovado: o plataforma-web fica bloqueado aguardando o importacao-notas-worker. Não há evidência de CPU local relevante.

Evidência na origem: importacao-notas-worker, nfse/rest/auth/emissor/nova-nota, 5.000 requests.

p50 p95 p99 max >10s >60s pending non-200
3.58s 8.80s 49.92s 74.38s 233 22 191 140

O código confirma POST síncrono para o Notas Worker e read timeout de 600s.

Quickwins
  • Reduzir timeout do call síncrono e retornar erro controlado.
  • Logar duração da chamada ao Notas Worker com trace/correlation id.
  • Avaliar min_idle_instances no importacao-notas-worker.
  • Se o contrato permitir, transformar emissão longa em fluxo assíncrono/semi-assíncrono.

3. Impostos v3/v4

Problema comprovado: Apdex ruim por tolerados; o init é um agregador síncrono com múltiplas dependências. Os dados atuais não sustentam culpar uma dependência única.

Quickwins
  • Instrumentar duração por etapa dentro de ImpostosAPagarCompositionRoot.executar().
  • Aplicar timeout/fallback em dependências não essenciais para render inicial.
  • Remover dados secundários do payload inicial e carregar por lazy load.
  • Garantir hit de cache para consulta-detalhe-imposto-api.

4. Dashboard v2

Problema comprovado: o init espera todos os cards; quando card_notas_fiscais ou card_impostos demora, o dashboard inteiro demora.

O código mostra chamadas síncronas de faturamento/notas em FaturamentoService.buscarFaturamento(), incluindo chamada ao monólito e NFeAPI.getFaturamentoMensal.

Quickwins
  • Cache curto por empresa para dados de faturamento dos cards, 30–60s.
  • Timeout/fallback por card para não travar o init inteiro.
  • Lazy load para card_notas_fiscais e card_impostos.
  • Instrumentar separadamente faturamentoMensal e NFeAPI.getFaturamentoMensal.

5. Infraestrutura

Cold start não explica o Apdex geral do plataforma-web, mas aparece em outliers de dependências.

Evidência: importacao-notas-worker teve 191 requests com pending na amostra de emissão; faturamento-worker /simuladores/fator-r tem p95 baixo, mas outliers com pending.

Quickwins
  • Avaliar min_idle_instances primeiro no importacao-notas-worker.
  • Avaliar min_idle_instances no faturamento-worker apenas se os outliers forem relevantes para horários críticos.
  • Não tratar escala do plataforma-web como causa principal sem nova evidência.

6. Prioridade recomendada

  1. Novo emissor: timeout controlado + investigação no importacao-notas-worker.
  2. Dashboard: cache curto + timeout/fallback/lazy load nos cards caros.
  3. Impostos: instrumentação por etapa antes de mexer em arquitetura.
  4. Infra: ajuste de min instances somente nos serviços com pending comprovado.
